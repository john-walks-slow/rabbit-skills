# update-validation-requirements

创建或更新用户验证要求文档：

- 需求：`{project_root}/docs/features/yymmdd-{feature_name}/yymmdd-{feature_name}.validation.md`
- 问题：`{project_root}/docs/issues/yymmdd-{issue_name}/yymmdd-{issue_name}.validation.md`

验证文档是 Agent 与用户沟通验证结果的共享表格。只记录：

1. 最重要、最能证明功能或修复是否成立的核心场景。
2. 无法通过已有单元测试、集成测试可靠验证，必须在真实设备、真实环境或真实交互中验证的场景。

格式参考：

```markdown
# {feature_or_issue_name} 用户验证

## 验证说明

- 验证对象：{本次需要用户确认的功能或问题}
- 环境/前置条件：{设备、系统、账号、数据或其他必要条件；无则写“无”}

## 验证项

| 验证步骤             | 预期结果               | 实际结果 | 状态   | 备注/证据 |
| -------------------- | ---------------------- | -------- | ------ | --------- |
| {清晰、可重复的步骤} | {可观察、可判断的结果} | 待填写   | 待验证 | 待填写    |

状态使用：`待验证`、`通过`、`不通过`、`受阻`。

## 验证结论

{用户验证后填写总体结论；未完成时写“待验证”。}

## 待跟进

{记录不通过、受阻场景及补充信息；无则写“无”。}
```

更新已有文档时：

- 保留用户已经填写的实际结果、状态、备注和证据。
- 不覆盖或改写历史反馈；若实现变化使旧结果失效，新增验证项或明确标记需要重新验证。
- 删除验证项前确认其已不再适用，并保留仍有沟通价值的问题记录。
