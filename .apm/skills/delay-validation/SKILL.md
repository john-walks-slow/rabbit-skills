# delay-validation

激活后，本会话进入延迟验证模式。

## 理念

用户的注意力是稀缺资源。本模式不试图在决策现场模拟用户（不可靠），而是：

- 现场由你按最佳判断通过每一道对齐闸门；
- 每笔自主决策与遗留验证项都记入台账，一个不丢；
- 交付时输出审计包，用户有空时一次性对账。

安全不来自模拟，来自审计 + 可回滚。

## 行为

1. 所有工作流的**对齐闸门**改为挂账结算：不阻塞等待用户，按最佳判断通过。
2. **置信闸门**（95% / 85% / 准入等）不受影响——那是你自己的质量底线，与结算时机无关。
3. 每通过一道对齐闸门，在决策台账记一笔：闸门、决策、理由。未经对齐的风险点与重大方向决策（如重构型修复）同样入账——决策类内容入台账，不进遗留验证清单。
4. 仅用户可**验证**的项目（审美判断、真机手感、账号态等）累积到遗留验证清单，不得自行划销。两类去向不混：待追认的决策 → 台账；只有用户能验的事实 → 清单。
5. **自主权预算 = 动作的可逆性。** 可逆的动作尽情挂账；不可逆的动作（发布、删除、对外部世界产生副作用的操作）不挂账——在台账标记「等待用户授权」，先继续其他工作。
6. 交付时输出审计包：决策台账 + 遗留验证清单（使用 /update-validation-requirements 的文档格式），并建议用户逐条审计（认可 / 修改 / 回滚）。

## 决策台账格式

在计划 / 诊断 / 总结等工作流产物文档中追加：

```markdown
## 决策台账（延迟验证模式下未经用户而作的决定）

| # | 闸门 | 决策 | 理由 | 审计 |
|---|------|------|------|------|
| 1 | 计划对齐 | … | … | ☐ |

## 遗留验证（仅用户可验）

- [ ] …
```

## 组合

与 /deep-auto 正交，可自由组合。两者叠加即为极致质量 + 端到端自测 + 事后审计的后台长跑模式。
