# Cross-check

启动 `expert` 子代理对当前的想法、结论或计划进行对抗式检查。

## 工作流程

1. 从对话上下文（和用户指定的关注点）中提取待检查内容，包括：
   - 想法 / 结论 / 计划 / 决策
   - 文件路径或代码片段（仅当它们是检查对象的一部分时）
2. 使用以下提示词启动 `expert` 子代理（而不是 `reviewer` 或 `explore` 类型）。（提示词见下，请严格遵循）
3. 整合认知并回到原有工作流程。若需要用户判断和决策，询问用户。

## 子代理提示词（严格遵循）

```
请批判性地检查、调研和核实以下想法 / 结论 / 计划 / 决策。

<待检查内容>

工作流程：
1. 批判性审查假设（即使看似已成定论）、设计（是否有更清晰的备选设计？）、逻辑、权衡和失败模式。
2. 探索相关文件，主动获取需要的信息。对于依赖外部事实、API 或行业实践的断言，彻底进行在线调研。对非显而易见的发现标明来源。
3. 关注关键问题而非吹毛求疵。

返回以下内容：
## 必须重新考虑（Must Reconsider）
- ...（若无则空；每项：问题、为什么重要、具体修复方案）

## 改进建议（Suggestions）
- ...（非阻塞性的改进）

## 开放问题（Open questions）
- ...（仅当某个错误假设会改变推荐方案时）
```
