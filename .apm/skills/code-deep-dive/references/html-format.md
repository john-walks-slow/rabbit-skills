# HTML 格式约定

当用户要求 `format=html` 时，使用 `scripts/md2html.py` 将 markdown 文章转换为单文件 HTML。转换器识别文章中的**约定标记**来渲染互动元素。

## 何时使用

- 用户在请求中说明 `format=html`（或"生成 HTML 版""要网页版"）。
- 默认仍是 markdown。`format=html` 是**可选增强**，不改变写作内容——文章先在 markdown 里写成约定格式，再用脚本转换。
- 转换后**同时保留** markdown 原文和 HTML 版本（`.md` 与 `.html` 并存于同一目录）。

## 用法

```bash
python <skill路径>/scripts/md2html.py <文章.md>
```

输出到与输入同目录的同名 `.html`（也可指定第二个参数作为输出路径）。依赖 `markdown` 与 `pygments`（`python -m pip install markdown pygments`）。

## 转换器自动做的事

不需要特殊标记，脚本自动处理：

- **目录（TOC）**：所有 `##` / `###` 标题自动生成侧边目录，滚动时高亮当前章节；桌面端可折叠（收起后正文自动居中），移动端为抽屉。
- **阅读进度条**：页面顶部进度条，随时知道读了多少。
- **代码语法高亮**：代码块按语言（```lang）高亮，等宽字体、圆角卡片、头部有语言标签 + **软换行开关** + **复制按钮**。
- **暗色/亮色切换**：右上角切换，**默认跟随系统偏好**，用户选择后记忆。
- **滚动渐入**：标题、表格、代码块、测验卡片滚动进入视口时淡入（柔和动效）。
- **预计时长（自动计算）**：脚本按正文中文字符数、代码行数、表格字数自动估算——
  - 正文每个标题旁显示「约 X 分钟」徽章；
  - **页脚显示全文总时长**；
  - 目录（TOC）中**不**显示每节时长。
  **写作时不要手动写时长**（如 `> 约 X 分钟` 或标题里的「（约 X 分钟）」），脚本会自动去除并重新估算。
- **modern 滚动条**：全站滚动条统一为细圆角样式，浅色深色下均适配。
- **打印样式**：`Ctrl+P` 时隐藏目录和进度条，输出干净的打印版。

## 约定的互动元素（markdown 中写）

### 通用语法规则

所有约定块（quiz / details / mermaid）遵循统一的开启/闭合规则：

- **开启标签**：`:::name`，独占一行。`name` 后面可跟参数（如 details 的标题），参数与 `:::name` 之间用空格分隔。
- **闭合标签**：独占一行。支持两种写法：
  - **显式闭合**（推荐）：`:::/name`（如 `:::/quiz`、`:::/details`、`:::/mermaid`），与开启标签配对，语义清晰，推荐使用。
  - **纯闭合**：`:::`（三个冒号），作为通用闭合符。脚本会按最近的开启标签自动配对。写法更简洁，但块嵌套时需小心。
  - 两种写法脚本都接受，作者可按喜好选择。同一篇文章内混用两种写法没有问题。
- **空行**：开启标签与内容之间建议留一个空行；闭合标签前也建议留一个空行。脚本会自动剥离多余的空白，但留空行可读性更好。
- **嵌套**：约定块之间**不要**互相嵌套（例如不要在 quiz 里嵌 details）。如需在折叠块里放代码或列表，用普通 markdown 即可。

### 1. 测验（可交互，支持问答与选择题）

用 `:::quiz` / `:::/quiz` 包裹。

**问答型**——条目用 `Q:` 和 `A:` 前缀，可多条答案，点击问题展开：

```markdown
:::quiz

Q: `useState` 返回的 setter 触发更新后，组件会发生什么？

A: 组件重新渲染，React 会用新的 state 值再次调用组件函数。
A: 渲染后 DOM 与上一次的差异会被提交（commit）到页面。

:::/quiz
```

**选择题**——`Q:` 后跟 `- 选项`，用 `答案:` 标注正确项（写选项文字或编号均可），用 `解说:`（或 `解释:`）给出解说。**选择后无论对错都显示解说**（有解说时），错误时正确项被标出：

```markdown
:::quiz

Q: 错误处理中间件的签名为什么必须保留 4 个参数？

- 靠注释标注
- 靠函数参数个数是否为 4
- 靠函数名包含 error

答案: 靠函数参数个数是否为 4

解说: Express 靠 `fn.length`（函数声明的参数数量）区分普通中间件和错误处理中间件。即便用不到 `err` 也必须保留 4 个参数，否则错误永远不会被捕获。

:::/quiz
```

- 正确选项**不会**预先打勾，选择后才用 ✓/✗ 标出。
- 测验放在每个核心章节末尾（自测），或第 8 章"要点速查卡"中。
- `答案:` 与 `解说:` 必须独占一行，前缀冒号支持半角 `:` 或全角 `：`。`解说:` 可省略（省略时选择后只给出对错反馈）。

### 2. 折叠块（答案/细节收起来）

用 `:::details 标题` / `:::/details` 包裹：

```markdown
:::details 为什么这里用 Map 而不是对象？

代码里 `const db = new Map()` 的键是数字 id。用对象的话，键会隐式转成字符串，
而 Map 保留原始类型——这决定了 `store.remove` 里 `db.delete(Number(id))`
为什么要先 `Number()` 转换。

:::/details
```

- **标题**：紧跟在 `:::details` 后面，用一个空格分隔，独占开启行。标题是这一行 `:::details` 之后到行尾的全部文本——**不要**用「」或【】等括号包裹（旧版曾允许省略括号，现已统一要求不加括号）。
- **正文**：标题行之后另起一行开始，可包含任意 markdown（段落、列表、代码引用等）。
- 渲染为：可折叠的 `<details>` 块，点击展开。用于：答案先隐藏、延伸阅读、容易让人分心的细节。

### 3. 图表（Mermaid）

用 `:::mermaid` / `:::/mermaid` 包裹标准 Mermaid 语法（flowchart / sequenceDiagram / gantt 等），浏览器端渲染：

```markdown
:::mermaid
flowchart TD
  A[请求到达] --> B[logger 中间件]
  B --> C{auth 是否通过?}
  C -- 否 --> D[401 短路]
  C -- 是 --> E[路由处理]
:::/mermaid
```

- 配色跟随浅色/深色主题，切换主题后自动重绘。
- mermaid 源码块前后**不需要**额外留空行（脚本会处理），但建议在 `:::mermaid` 与正文之间留一个空行，便于阅读。

### 4. 图标（lucide）

正文可用 `{{icon:名称}}` 插入 lucide 图标（如 `{{icon:zap}}`、`{{icon:lightbulb}}`、`{{icon:git-branch}}`），图标名见 [lucide 图标库](https://lucide.dev/icons/)。用于章节标题前缀点缀、要点强调，不要滥用。

### 5. 代码引用（引用项目源文件）

当你引用项目源代码片段时，用**代码引用**格式代替普通代码块。语法：

````markdown
```startLine:endLine:filepath
<代码内容>
```
````

- `startLine` / `endLine`：被引用片段在源文件中的起止行号（整数）。
- `filepath`：源文件相对路径（如 `src/lib/chat/llm.ts`）。脚本会显示在代码块头部，并按扩展名自动推断语法高亮语言。
- 如需附注，可在 filepath 后加一个空格再写备注，如 ` ```952:1070:src/components/chat/MessageItem.tsx (引用) `——备注会被忽略，不影响渲染。

示例：

````markdown
```1:57:src/lib/chat/llm.ts
export interface StreamChatOpts {
  id: string;
  baseUrl: string;
  // ...
}
```
````

渲染效果：圆角代码卡片，头部显示 `src/lib/chat/llm.ts`（而非语言名），自动按 `.ts` 推断为 TypeScript 高亮，左侧带行号（从 1 开始）。软换行开关与复制按钮同普通代码块。

如果你写的代码**不是**项目源文件片段（如示意代码、JSON 示例），仍用普通代码块：

````markdown
```typescript
const x: number = 1;
```
````

普通代码块用语言名作 info string，头部显示语言名，不带行号。

### 6. 表格、代码块、引用

- 表格：标准 markdown 表格，自动增强样式（斑马纹、圆角、悬停）。
- 普通代码块：```lang 指定语言，自动高亮；头部有软换行开关与复制按钮；移动端可横向滚动。
- 引用块：强调引用、注意事项。

## 写作时的位置约定

1. 先按 `references/article-template.md` 正常写 markdown 文章。
2. **测验**放在每个核心章节末尾（自测），或第 8 章"要点速查卡"中。
3. **折叠块**用于：答案先隐藏、延伸阅读、容易让人分心的细节。
4. **图表**用在讲机制、流程、调用链、时序的章节。
5. **不要**手动写预计时长——脚本自动估算。

## 转换后检查

转换完成后打开 HTML 快速检查：

- 标题是否全部进目录，锚点跳转是否正常；目录收起后正文是否居中。
- 代码块高亮是否正确（语言名写对了没有），字体是否为等宽、软换行/复制是否可用。
- 测验卡片：选择题点击后是否显示 ✓/✗ 与解说（对错都要出），问答点击是否展开。
- Mermaid 图表是否渲染、随主题切换是否重绘。
- 移动端宽度下目录是否隐藏、正文是否可读。
- 暗色/亮色下表格、代码块、图表是否可读；时长徽章与页脚总时长是否显示。
