# 文章结构模板

每篇深度长文按此结构撰写。章节编号与标题可随主题微调，但**顺序逻辑不变**：先给动机 → 补前置 → 讲核心 → 看真实代码 → 深入底层 → 讲实战 → 给资料 → 收尾复盘。

括号内为该章节的**预计学习时长**，约 90 分钟总量，正文 10000-15000 中文字符。

> 关于时长：markdown 版中，`（约 X 分钟）` 写在章节标题里即可（或章首写 `> 约 X 分钟`）。`format=html` 时转换脚本会自动清除标题中的「（约 X 分钟）」并按其字数/代码量重新估算，无需手动调整。

---

## 头部元信息

```markdown
> **主题**：XXX 原理深挖
> **来源项目**：<项目名>（<仓库/目录位置>）
> **学习时长**：约 90 分钟
> **前置知识**：会读 Python/JS 代码；无需了解 <主题>
> **写作日期**：2026-08-07
```

## 0. 快速导航（约 2 分钟）

- 本文讲什么（一段话）。
- **学习目标**：学完你能做到什么，3-5 条，动词开头（如"能说清 useState 内部如何触发重渲染"）。
- **章节地图**：每章一句话 + 预计分钟数。帮助读者按碎片时间选章节。
- 如果你已经懂某部分，明确告诉读者可以跳哪章。

## 1. 为什么值得学（约 5 分钟）

- 这个主题在你的项目里承担什么角色（它在哪、被谁用、管什么事）。
- 学完的直接收益：对指挥 AI / 审查 AI 产出 / 排查 bug 的具体帮助。给真实场景，不喊口号。
- 一个"你知道按钮，但按钮背后是什么"的钩子：从项目里一个具体用户可见行为切入。

## 2. 前置概念速通（约 10 分钟）

- 主题依赖的背景概念，每个 100-200 字讲清，默认读者零基础。
- 每个概念给：一句话定义 → 生活中的类比（可选但加分）→ 最小例子。
- 与本篇无关的过深细节不要展开，给出"想深入可以看资料库第 X 条"。

## 3. 核心机制（约 20 分钟）

- 主题的核心工作原理，**从零到深入**，分小节递进。
- 结构：概念 → 直觉（类比/图示）→ 机制细节。
- 覆盖主题全貌，不局限于项目用到的子集（深度优先原则）。
- 关键设计权衡要讲：为什么这样设计、代价是什么。

## 4. 项目代码逐段解读（约 30 分钟）

**本文的核心章节。** 用项目真实代码把核心机制落地。全文代码量约 1000 行，本章占大头。

- 每段代码完整内嵌，代码块上方标注来源（`src/auth/jwt.py`），下方逐段解读。
- 解读顺序：这段代码在干什么 → 关键行逐个讲 → 与第 3 章的概念如何对应 → **这段代码有没有问题**（设计缺陷、技术债、可疑取舍，代价是什么，通常更好的做法）。
- 代码内部存在依赖关系时，先给一个"全景图"（这段代码的调用关系），再逐段看。
- 删减原文时要明确说明省略了什么（如"此处省略了日志与重试逻辑，共 20 行"）。
- 至少有一段"逐行走查"：模拟一次具体输入，逐步推演代码如何执行（这是最容易讲出深度的地方）。
- 核心代码讲透，周边的代码（被调用的函数、依赖的工具、相邻模块）按关联程度纳入讲解，保证读者把这一片代码"连成片"理解。

## 5. 深入底层（约 15 分钟）

- **超越项目本身**：主题的底层实现原理、历史演进、设计哲学。
- 示例：讲 React Hooks 就讲 Fiber 协调与 Hook 链表；讲 asyncio 就讲事件循环与协程调度；讲 Docker 就讲 namespace 与 cgroup。
- 这一章是"深度优先"原则的体现，也是拉开与普通教程差距的地方。
- 内容较多时可拆成多个小节，每个小节仍保持自包含。

## 6. 运行行为与排查路径（约 10 分钟）

代码讲解的自然延伸：讲清这段代码**在真实运行中会怎样表现**，以及**如何从现象定位到代码**。仍是讲解，不是评判。

- 代码的关键运行路径：正常路径、边界情况（空输入、重复请求、并发）、错误路径分别怎么走。
- 项目里与主题相关的典型现象：报错信息长什么样、日志怎么流、数据不一致是怎么产生的——从现象到代码的对应关系。
- 排查路径：遇到这类问题，从哪个入口看起、看哪些日志、断在哪里。给具体可操作的线索。

## 7. 学习资料库（约 5 分钟）

- 外部链接按"入门 → 进阶 → 权威"分三组，或按子主题分组。
- **每个链接必须配一句话说明**：讲了什么、适合什么阶段。用户在手机/平板上随时能点开——说明文字帮他们判断"现在值不值得点开"。
- 数量 ≥ 12 个，覆盖官方文档 / 教程 / 博客 / 视频等类型。链接须真实有效。
- 中文资料和英文资料都要有；英文资料注明"英文"。

## 8. 要点速查卡（约 3 分钟）

- 10-15 个全文核心要点，每点一句话（可含最小代码示例）。
- 定位是"复习卡"：读者随时翻回这一节就能唤起全文记忆。
- 如果适合，结尾给一句"下一步建议"：学完这篇之后可以再学什么主题。
