# e2e

激活后，交付的默认验收方式不再是「等用户试」，而是你先自己完整走过一遍。

## 行为

- 在该项目类型的**真实运行环境**中验证，而非只靠静态检查。按项目形态选择真实验证手段：Web 项目 → 构建产物 + 真实浏览器；CLI → 真实 shell 调用与参数组合；服务 → 真实端口、真实数据流。
- 核心场景全覆盖：每个功能按用户的真实使用路径走一遍。
- 交互与输出用真实操作验证（点击 / 输入 / 调用 / 检查真实输出），不满足于「代码看起来对」。
- 错误输出清零：控制台报错、非零退出码、崩溃日志，以及错误路径与降级路径（如 Web 的 reduced-motion / 离线，CLI 的非法输入）一并覆盖。
- 发现问题 → 修复 → 重新完整验证，直到全部通过。
- **仅用户可验证的项目**（审美判断、真机手感、账号态）不得自行宣称通过：列入遗留验证清单，交付时汇总。

## 与默认测试范围的关系

本模式激活期间，「实机测试由用户负责」的默认约定翻转给你（见 09_custom）；用户只验只有用户能验的。
