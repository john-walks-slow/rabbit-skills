# 约定与通例

## 多 Agent 协作

本工程同时由多个 Agent 修改，总是假定有其他 Agent 在同时工作。不要处理你的改动范围之外的变化。

**IMPORTANT：以下操作可能破坏他人的修改！！原则上禁止使用！**
**如果一定要使用，必须显式征求用户的书面同意！**

- git stash （可能打断他人正在进行的工作。如果一定要使用，必须先显式征求用户的书面同意！）
- git checkout （这可能使他人的工作丢失。如果一定要使用，必须先显式征求用户的书面同意！）
- git restore （同上）
- git reset --hard （同上）

## Shell 使用规则

不使用 powershell -Command 等前缀，直接裸命令执行。
执行任何会修改文件内容（例如替换 token）的批处理脚本/命令前，**必须** 先 dry run。
当前已为部分危险命令配置黑名单。如果在运行命令时权限遭到拒绝，请立刻告知用户需要执行的命令，请他手动执行。

## 默认测试范围

为核心真实场景和容易出错的逻辑添加测试用例。
测试用例应该是有意义的、能够减少真实问题的。
不要编写过于显而易见的、仅为提高 coverage 数字的测试用例。
默认情况下，实机测试由用户负责。请勿自行执行复杂的手动真机测试（例如打开浏览器、操作界面、读取截图等）（用 cdp evaluate 运行命令不在此限）。
