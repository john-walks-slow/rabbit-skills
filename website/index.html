PHILOSOPHY · 哲学

把判断力留给 Agent，
把决策权留给你。

大多数 Agent 框架用重型流程把模型捆起来。rabbit-skills 反其道而行： 用最少的、松弛的规则，守护真正要紧的事——调研先于动手、定位先于修复、交付必须经过检视。 只定义委托边界，不微操模型动作。随模型进化也不过时。

"

控制的目标不是剥夺系统的自由度，而是界定安全的可行域，让系统在可行域内释放最大化的调节能力。

— Ashby · 必要多样性定律 阅读全文 →

松弛的约束

规则简洁清晰，不预设重型流程。把判断力留给 Agent，需要更强约束时再按项目加码。

零学习成本

不绑定任何开发范式——TDD、spec-driven，需要时再引入。读一遍 Readme 即可上手。

子代理隔离

调研、检视、复核交给独立上下文的子代理——显著减少幻觉，避免对错误结论的路径依赖。

化繁为简的文档

极简文档策略：给新成员 Quick Start、把关键历史留作记录，不在文档里重述代码。

标准 APM 打包

基于微软 APM 规范。一份 apm.yml，九大主流 Agent 工具一次接入。

THREE WORKFLOWS · 核心工作流

三条工作流，覆盖 AI 原生开发全程。

每条工作流是一道带置信闸门的轨道：状态到位才允许通过。

01 / RESEARCH → PLAN → ALIGN

调研与规划

/workflow-research-plan

中等以上规模的需求，先作为产品架构师完成调研与设计：全面理解意图与既有代码、 网络调研外部方案，再设计体验与架构，最后与你对齐——直到计划与期望完全一致。

  • 95% 把握掌握背景资料后，才允许进入设计
  • explore / deep-researcher 子代理独立调研
  • 选型犹豫或事关重大时，自动触发 cross-check
  • 产物：docs/features/*.plan.md

"当你有 95% 把握掌握了充分、完备的背景信息和网络资料后才进入下一步。"

02 / REPRODUCE → ROOT CAUSE → DIAGNOSE

根因排障

/workflow-troubleshoot

复杂问题先定位再修改，避免越改越错：先复现问题、确定回归验收标准， 再做根因分析——你的分析必须能解释用户看到的全部现象。置信不足 85%，不许输出诊断。

  • 测试用例或实机日志完整复现后才继续
  • 不假装明白、不盲目修复——问题只会扩大
  • 单点修复 / 重构型修复，两条路径供你选择
  • 产物：docs/issues/*.troubleshoot.md

"当且仅当你对于根因的确信度大于 85% 时，才输出诊断结论。"

03 / IMPLEMENT → TEST → REVIEW → VALIDATE → DOC → COMMIT

实施与交付

/workflow-implement-review

无论需求开发还是问题修复，统一走六步交付：实施、测试、独立子代理检视、 用户实机验证、文档沉淀、干净提交。每一步都有明确的放行条件。

  • reviewer 子代理独立检视，未达准入就再来一轮
  • 核心场景必须实机验证，用户书面确认才前进
  • 连续修改未达预期 → 强制退回 troubleshoot
  • 产物：*.review.md · *.summary.md + commit

"直到拥有准入或条件准入结论后，才进入下一步。"

另有两条工作流协同作战：/workflow-manage-tasks 任务分派 · /workflow-leader 项目领导。 在内容物浏览器查看全部 →

DOCUMENTS · 文档

留档，而非重述代码。

rabbit-skills 产出几类轻量文档：记录决策、证据、经验——那些代码自身说不清的事。 它们不为重述代码存在，而为留档：让下一个 Agent（或人）接手时不从零开始。
